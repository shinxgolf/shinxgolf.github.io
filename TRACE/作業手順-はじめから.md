# 作業手順 — はじめから（通し手順書）

> ゼロから「動くデモ」までを、順番にクリック単位で並べたもの。
> 専門用語は最小限。各フェーズに ☐ チェックと所要目安を付けた。
> 細かい数式は `runbook/画面づくり-コピペ手順.md`、フローは `flows/` に分けてある（本書はそこへ誘導する）。

全体の地図：
```
A 準備  →  B サイト作成  →  C データ層を自動作成  →  D アプリの器を作る
      →  E 画面づくり  →  F フローづくり  →  G 仕上げ・リハーサル
```

## フェーズA：準備（約30分・最初の1回だけ）

- ☐ **A-1. 会社アカウントの確認**
  ブラウザで https://www.office.com を開き、会社の Microsoft 365 アカウントでサインインできることを確認。
- ☐ **A-2. 権限の確認**
  SharePoint で「サイトを新規作成」できる権限があるか（無ければ情シスに「チームサイトを1つ作って所有者にして」と依頼）。
- ☐ **A-3. PowerShell 7 を入れる**
  https://aka.ms/powershell からインストーラを入れて実行 → 完了後、スタートメニューで「PowerShell 7」を起動できればOK。
  （Windows標準の「Windows PowerShell 5.1」でも動くが、7推奨）
- ☐ **A-4. このリポジトリを手元に置く**
  GitHub の `shinxgolf/shinxgolf.github.io` を「Code → Download ZIP」で落として展開（または `git clone`）。
  `TRACE` フォルダの場所を覚えておく（例：`C:\Users\you\Downloads\shinxgolf.github.io-main\TRACE`）。

> pac（アプリのコード化）はフェーズEより後でしか使わないので、ここでは入れなくてよい。

## フェーズB：SharePoint サイトを作る（約10分）

- ☐ **B-1.** https://www.office.com → 左の「SharePoint」を開く
- ☐ **B-2.** 「＋ サイトの作成」→「チームサイト」を選ぶ
- ☐ **B-3.** サイト名に `TRACE` と入力 → 次へ → 既定のまま「完了」
- ☐ **B-4.** 作成後の URL を控える。形は：
  ```
  https://<会社名>.sharepoint.com/sites/TRACE
  ```
  この URL を次のフェーズで使う。

## フェーズC：データ層を「コマンド1つ」で作る（約15分）

ここが**完全自動**の部分。5つのリスト作成＋サンプルデータ投入まで一気に終わる。

- ☐ **C-1.** 「PowerShell 7」を起動
- ☐ **C-2.** TRACE の scripts フォルダへ移動（パスは自分の場所に変える）：
  ```powershell
  cd "C:\Users\you\Downloads\shinxgolf.github.io-main\TRACE\scripts"
  ```
- ☐ **C-3.**（初回のみ）スクリプト実行を許可：
  ```powershell
  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
  ```
  （このウィンドウの間だけ有効。安全）
- ☐ **C-4.** ワンコマンド実行（URL は B-4 のもの）：
  ```powershell
  ./Deploy-TRACE.ps1 -SiteUrl "https://<会社名>.sharepoint.com/sites/TRACE"
  ```
- ☐ **C-5.** 途中で **PnP.PowerShell のインストール確認**が出たら `Y`（はい）。
- ☐ **C-6.** **ブラウザ認証**の画面が開く → 会社アカウントでログイン → 「承諾」。
  （初回は管理者の同意が要ることがある。出たら情シスへ）
- ☐ **C-7.** 緑色で「✅ データ層の自動展開が完了しました」が出れば成功。
- ☐ **C-8.** SharePoint の TRACE サイト →「サイト コンテンツ」を開き、
  `TRACE_Intermediaries / TRACE_Customers / TRACE_Cases / TRACE_VisitHistory / TRACE_Settings`
  の5リストとデータが入っていることを確認。

### 担当者を「実在の人」にしたい場合（任意）
サンプルの担当者は架空メールなので、そのままだと全員「未割当」になる（未割当プールのデモにはなる）。
実メンバーに割り当てたいなら、実行前に：
- `TRACE/demo-data/user-map.csv` を開き、`RealEmail` 列に実在メールを書く、**または**
- コマンドに `-DefaultAssignee "あなた@会社.com"` を付けて全部を自分に寄せる：
  ```powershell
  ./Deploy-TRACE.ps1 -SiteUrl "https://...sharepoint.com/sites/TRACE" -DefaultAssignee "you@contoso.com"
  ```

### つまずいたら
| 症状 | 対処 |
|---|---|
| `実行できない/ポリシー` | C-3 をやり直す |
| `PnP が無い` | `Install-Module PnP.PowerShell -Scope CurrentUser` を手動実行 |
| `認証で止まる/権限エラー` | 別ブラウザで会社アカウント確認／情シスに同意依頼 |
| その他の赤いエラー | **エラー文をそのままコピーして共有**してくれれば直す |

## フェーズD：Power Apps の「アプリの器」を作る（約10分）

- ☐ **D-1.** https://make.powerapps.com を開く（右上が会社アカウントか確認）
- ☐ **D-2.** 左「＋ 作成」→「空のアプリ」→「空のキャンバスアプリ」
- ☐ **D-3.** アプリ名 `TRACE`、形式は **電話** を選んで「作成」
- ☐ **D-4.** 左の「データ」アイコン →「データの追加」→ `SharePoint` を選ぶ → さっきの TRACE サイトを選択
- ☐ **D-5.** 5つのリスト全部にチェック →「接続」
- ☐ **D-6.** 左上「設定 →（今後の）機能」で **「Navigate in App.OnStart」を OFF** にしておく（推奨）
- ☐ **D-7.** 右上の保存（クラウド）を押しておく

これで「中身は空だがデータに繋がったアプリ」が用意できた。次から中身を作る。

## フェーズE：画面づくり（半日〜2日）

ここからは **`runbook/画面づくり-コピペ手順.md` を上から順に**進める。
（完成形の見た目は `prototype/index.html` をブラウザで開いて、横に置きながら作ると速い）

最初の3ステップだけ、さらに噛み砕いておく：

- ☐ **E-1. STEP1（テーマ・初期化）**
  画面ツリーの一番上「App」をクリック → 中央上のプロパティ欄を `OnStart` に切替 → 手順書 STEP1 の式を貼る →
  「App」を右クリック →「OnStart の実行」。
- ☐ **E-2. STEP2（画面を7枚）**
  左の「＋ 画面の追加」→「空」を7回 → それぞれ右クリックで名前変更（`scrHome` 等）→ 各画面の `Fill` に `gPrimary`。
- ☐ **E-3. STEP3（下のナビ）**
  画面下に「四角形/コンテナ」を置きボタン4つ → 手順書の `OnSelect` と `Color` を貼る → できたらコピーして他画面へ貼る。
- ☐ **E-4. 以降** STEP4〜9（ホーム/一覧/詳細/記録/プール/ダッシュボード）を手順書どおり。
  各ステップの ☐ を潰しながら、こまめに右上「保存」＋ ▶ プレビューで確認。

> コツ：1画面できるたびに ▶ で動かし、プロトタイプと見比べる。完璧を後回しにして「全画面ざっと→後で詰める」が速い。
