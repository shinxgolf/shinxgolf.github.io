# Power Automate フロー一式

TRACE の自動化（通知・週次報告・最終接触日の更新・AI）を担う **7本のフロー**です。
各ファイルは「そのまま貼れる式」入りの **作成仕様**になっています。Power Automate（make.powerautomate.com）で
上から順に作ってください。テナント未接続でも式は確定済みなので、迷わず組めます。

> なぜ .zip 一括インポートではなく「仕様」なのか
> フローのソリューションzipは接続参照(connection reference)を手作業で繋ぎ直す必要があり、
> 実テナントでの確認なしに渡すと結局つまずきます。**確実に動く式を渡す**方が速くて安全です。

## 作る順番（MVP優先）

| # | フロー | 種類 | 優先 | ファイル |
|---|---|---|---|---|
| ① | 最終接触日の自動更新 | 自動（リスト作成トリガー） | ★MVP | `01-最終接触日更新.md` |
| ③ | マネージャー通知（毎朝8:00） | 定期 | ★MVP | `03-マネージャー通知.md` |
| ④ | 営業向け朝の通知（毎朝8:30） | 定期 | ★MVP | `04-営業朝通知.md` |
| ⑤ | 週次報告（設定曜日・時刻） | 定期 | ★MVP | `05-週次報告.md` |
| ② | 毎日アラート計算 | 定期 | 任意（将来の委任対策） | `02-アラート計算-任意.md` |
| ⑥ | AI要約（アプリから呼ぶ） | PowerApps起動 | Week1の判定次第 | `06-AI要約.md` |
| ⑦ | メール下書き | PowerApps起動 | Week1の判定次第 | `07-メール下書き.md` |

## 共通の前提（コネクタ＝接続）

初回に各コネクタへサインインが必要です。**フローの所有者はサービスアカウント推奨**（個人退職で止まらないように）。

- **SharePoint**（リスト読み書き）… ①②③④⑤
- **Microsoft Teams**（通知投稿）… ③④⑤
- **Office 365 Outlook**（メール下書き）… ⑦
- **AI Builder** または **Copilot/GPT**（要約）… ⑥（Week1で可否判定）

## 共通の小ワザ（つまずき回避）

- **日本時間で判定**：`utcNow()` はUTC。日本の曜日・日付は
  `convertTimeZone(utcNow(),'UTC','Tokyo Standard Time','...')` を使う（各仕様に記載）。
- **日付フィルタは OData でやる**：`LastContactDate lt '@{...}'` のように SharePoint 日付列は
  サーバー側で絞れる → 委任問題を回避でき、件数取得が速い。
- **未割当（担当者なし）の絞り込み**：Get items のフィルターで `AssignedToId eq null`。
  効かない環境では「アレイのフィルター」で `empty(item()?['AssignedTo'])` を使う。
- **設定値はリストから読む**：曜日・時刻・閾値・マネージャー宛先は `TRACE_Settings` を Get items で取得
  → フロー改修なしで運用変更できる。
